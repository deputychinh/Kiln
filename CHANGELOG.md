## [Unreleased]

### Added

- Lease heartbeat (KILN-24): a running job extends its 5-minute lease every 100 s on the database clock, guarded by its claim, so a job longer than its lease is not started by a second worker; the heartbeat stops when the job ends, when the claim is lost (logged once) or after 30 minutes (a hung job is then released like a crashed one), and logs database hiccups (as `DATABASE_UNAVAILABLE`) and retries at the next tick; it is stopped before any outcome is written and never extends an already-expired lease, and a worker reaping exhausted jobs buries one only while its lease is still expired; Postgres connections give up after 5 s
- Storage circuit breaker and bulkhead (KILN-23): after 5 consecutive storage failures the API and worker fail fast for 30 s (503 `STORAGE_UNAVAILABLE` with `Retry-After` = the cool-down left), then let one trial call through; at most 16 storage calls run at once (0.5 s wait for a slot, then 503 with `Retry-After: 1`). Signing URLs never touches the network, so listing and creating assets keep working during an outage; `/ready` fails at once while the circuit is open but its 1 s probes never open it; late answers of calls from before an outage are ignored, so only one trial runs at a time; refused calls log at debug and a saturated bulkhead warns at most once a minute; a failed trial answers with the new cool-down; listings are guarded per page fetch; the start-up bucket check never opens the circuit; `KILN_STORAGE_MAX_CONCURRENT` is at most 32; `Retry-After` is exposed to the web app. Settings `KILN_STORAGE_BREAKER_FAILURES`, `KILN_STORAGE_BREAKER_COOLDOWN_SECONDS`, `KILN_STORAGE_MAX_CONCURRENT`, `KILN_STORAGE_BULKHEAD_WAIT_SECONDS`, validated > 0
- Scheduled maintenance (KILN-22): at most once an hour across all workers (`KILN_MAINTENANCE_INTERVAL_SECONDS`, lease row on the database clock), the worker expires uploads never completed within 24 h (`failed` with the new reason `UPLOAD_EXPIRED`, migration `0004`), deletes old `uploads/` objects whose version is gone or no longer waiting (and the promoted final object when an expiry beats a completion), and purges expired idempotency keys; at most 500 expiries and 500 deletions per run, a listing cut after 5,000 keys, versions looked up 100 at a time; a storage outage stops only the storage work of that run; a completion that loses the race to an expiry removes the file it promoted and returns the expired version; expired keys are purged in up to 10 batches per run, one log line per run with counts only, failures logged without stopping job processing. The gallery explains `UPLOAD_EXPIRED` in English and Vietnamese
- Gallery and asset detail (KILN-6): `/assets` lists assets newest first as preview cards (kind as text, relative time with the exact date on hover) with loading, empty and error states and "Load more" cursor pagination; `/assets/<id>` shows the preview, facts and versions newest first with text status badges, sizes and readable failure reasons, refreshing every 3 s while a version is processing (for at most 5 minutes). Material 3 list-detail: one pane below 840 px (focus moves to the detail heading), list and detail side by side from 840 px with the open card marked `aria-current`. Previews that fail to load trigger one shared refresh of signed URLs per 15-minute signature lifetime (per list, per detail preview) and a failed URL is never reused (a refresh that would coincide with Load more waits for it); `ErrorState` takes `titleAs` (the compact detail's errors are the page h1) and its title uses the body text size; 4xx answers are never retried. Design system: `Badge`, `AssetThumb`, `Skeleton`, `EmptyState`, `ErrorState`; light-theme success/warning/danger tokens with ≥ 4.5:1 contrast. e2e publishes a PNG through the real API, storage and worker and waits for its preview. Review fixes: polling keeps still-valid signed preview URLs (no re-download every 3 s) and stops after 5 minutes; the gallery refreshes when processing ends; failed refreshes say the detail may be stale; focus returns to the card after going back and lands on the first new card after Load more; the detail heading is the page h1 when it replaces the list; relative times tick; `ErrorState` retry keeps focus while retrying
- Thumbnails (KILN-4): completion records the final ETag and queues a `thumbnail` job in the same transaction; the worker (`make worker`) claims jobs with `FOR UPDATE SKIP LOCKED` and a 5-minute lease, verifies the ETag, renders a 512 px WebP with allow-listed decoders only (a 50-megapixel check before decoding, EXIF orientation applied, metadata stripped), marks the version `ready` and makes it the asset's cover unless a newer version already is; bad files fail with `UPLOAD_CHANGED`, `UNREADABLE_IMAGE` or `IMAGE_TOO_LARGE`; storage outages retry after 5/25/125/625 s and give up with `PROCESSING_GAVE_UP`; the API returns `thumbnail_url` (signed, 15 min) for assets and ready versions and `failure_reason` for failed ones; migration `0003`; the worker stops cleanly on SIGTERM, survives errors and database outages, buries jobs that crash it repeatedly, guards every job update with its claim, uses the database clock for leases, downloads with `If-Match` and keeps each job within about 256 MB of memory (PNG/JPEG up to 50 MP, WebP up to 8 MP and 64 MB); 16-bit height maps are scaled rather than clipped; job starts are logged; migration `0003` backfills existing rows.
- Idempotent creation (KILN-21): `POST /api/v1/assets` and `POST /api/v1/assets/{id}/versions` accept an optional `Idempotency-Key` (sf-string per IETF draft-08); a repeat within 24 h replays the first result with `Idempotent-Replayed: true` (re-signing the upload form only while the version is `pending_upload`, otherwise `upload: null` — `upload` is therefore nullable in the contract, though a first creation always has one); a repeated `Idempotency-Key` header → `400`; reuse with another body or endpoint → `422 IDEMPOTENCY_KEY_REUSED`; a duplicate waits for the first request in the same transaction (`409 IDEMPOTENCY_KEY_IN_USE` past the lock timeout); invalid keys → `400`; failed requests do not store the key; migration `0002_idempotency_keys` and a purge function for expired keys.
- Uploads (KILN-3): `POST /api/v1/assets` and `POST /api/v1/assets/{id}/versions` return a presigned POST to a staging key that pins key, type and exact size (ADR 0004); `POST /api/v1/asset-versions/{id}/completions` checks the object and promotes it to an immutable final key with an ETag-conditional copy (ADR 0005), idempotent and resumable; list, detail and version reads; `/ready` checks Postgres and storage and creates the bucket; database lock and statement timeouts; storage timeouts with bounded retries; every error (database, unexpected) as problem details, `503` with `Retry-After`; 1 MB request body limit; documented problem responses in OpenAPI (`application/problem+json`, `Retry-After`, `Location`); concurrent completions are safe against real storage; `/ready` answers within about 1 s even when storage is down.
- Asset and version model (KILN-2): UUID v7 ids, name, file-name, media-type and size rules, the version life cycle, Postgres schema with database-enforced invariants, first Alembic migration, and a repository with keyset pagination, row-locked version numbering and compare-and-set status changes.
- Local S3 storage on SeaweedFS (ADR 0003) because MinIO images are no longer published.
- Repository bootstrap: Prettier, EditorConfig, husky + commitlint, Makefile, CI, docs (conventions, testing, ADR 0001–0002, architecture, security, design system, plan, backlog).
- API skeleton: `/health` and `/ready`, RFC 9457 problem details with stable codes, request ids, OpenAPI export.
- Worker skeleton with typed settings.
- Design system package with tokens (dark default, light theme, reduced motion) and `Button`.
- `kiln` CLI skeleton (`--version`, `--help`).
- Web app skeleton: app shell with skip link, API status through generated OpenAPI types, English and Vietnamese copy, Playwright smoke with axe checks.
