## Baseline

- Headers: CSP (no `unsafe-inline` scripts), HSTS, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`.
- CORS allow-list from `KILN_CORS_ORIGINS` (the local default lists the dev and preview ports on `127.0.0.1` and `localhost`; deployed environments set their own origins); the API allows `Content-Type`, `X-Kiln-Csrf`, `Idempotency-Key` and `X-Request-Id` request headers and GET, POST and DELETE. The same list is the CSRF Origin allow-list (KILN-12).
- Authentication (KILN-12): every endpoint except `/health`, `/ready`, sign-in and sign-out needs a session cookie or a Bearer token (`kiln_api/authentication.py`); one authorization policy (`domain/authorization.py`, ADR 0012); single workspace in v0.2. API answers carry `Cache-Control: no-store`; 401 carries `WWW-Authenticate: Bearer realm="kiln"`. Behind a reverse proxy run uvicorn with `--proxy-headers` and a forwarded-allow list so sign-in throttling sees client IPs.
- Browser uploads go straight to storage with the signed POST form (policy pins key, type and exact size, ADR 0004). The bucket's CORS rules must allow `POST` only from the app origins in every deployed environment; local SeaweedFS reflects any origin, which is acceptable only on a developer machine. The browser's own checks (type by extension, 1 byte–500 MiB) are for feedback; the API and the worker (magic bytes) stay the gate.
- Limits: request body 1 MB (`413 PAYLOAD_TOO_LARGE`, chunked bodies counted too); asset 500 MB; pagination `limit` 1 to 100 (`422` outside).
- Every error, including database and unexpected ones, is RFC 9457 problem details without internals; `503` carries `Retry-After`.
- Timeouts: Postgres `lock_timeout` 5 s and `statement_timeout` 15 s; storage 3 s connect, 10 s read, 2 attempts in total.
- Security events (sign-in, authorization denial, token revocation) are logged with ids and without secrets.
- Secrets only in env; `.env` never enters git.
