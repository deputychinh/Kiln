# KILN-36: Model debt from the KILN-9 review (worker part)

- Release: v0.2 · Status: doing · Owner: Claude (deliver-loop)

## Story

As an **art lead**, I want every model version marked ready to be one the 3D viewer can open, including versions published before the worker learnt its current rules, so that "ready" never means "the viewer will refuse it".

INVEST: Independent ☑ (worker and its repositories only) · Negotiable ☑ · Valuable ☑ (closes the KILN-9 review's open finding) · Estimable ☑ · Small ☑ (one reader rule, one command) · Testable ☑

**Split:** this cycle is the worker part. The copy change ("damaged or malformed model" instead of "not a glTF binary") is in `apps/web`, which another agent is redesigning right now; it is left for a later cycle and keeps this item open.

## Non-functional

- Security: the re-check reads files only through the same sandbox as the worker (ADR 0007); only the ETag recorded at completion is read (`If-Match`); only counts are logged (OWASP A09).
- Concurrency: every write is a compare-and-set on `status = 'ready'` inside one transaction with the cover change; the cover fallback is one `UPDATE` on the asset row, so it serialises with the worker's `promote_cover`.
- Performance: the graph check is O(nodes + children). The walk reads ready model versions by id in keyset pages of 100; Postgres can serve each page from `pk_asset_versions` (plan below), so a full run reads each row about once.
- Accessibility / UI: not touched (worker only).

## Out of scope

- The web copy change in KILN-36 (`apps/web`, under redesign) — a later cycle.
- Deleting the thumbnails of versions the re-check fails (nothing links to them once the cover moves).
- Running the re-check on a schedule: it is a one-off per rule change (ADR 0011).

## Design

- **Reader** (`kiln_worker/glb.py`): `check_node_graph()` runs before the scene walk. One pass over every node's `children` records each node's parent (a second parent fails "reached twice: it has two parents"); `_check_depths` follows parents to a root once per node with memoised depths (a loop fails "reached twice: the node graph has a cycle", depth over `MODEL_MAX_NODE_DEPTH` fails "too deep"); every scene must list valid, distinct, parentless nodes. The default scene is still the one drawn.
- **Life cycle** (`kiln_api.constants.ALLOWED_TRANSITIONS`): `ready → failed` is allowed; ADR 0011.
- **Repositories**: `AssetRepository.drop_cover(version)` (port + Postgres: `UPDATE assets SET cover_version_id = (newest other ready version) WHERE id = … AND cover_version_id = version.id`); `MaintenanceStore.ready_model_versions(after, limit)` (join `assets.kind = 'model'`, `status = 'ready'`, `ORDER BY id`, keyset).
- **Command** (`kiln_worker/recheck.py`, `make recheck-models`): `ModelRecheck.run()` pages ready model ids, loads them, and for each: over `MODEL_MAX_BYTES` → too large; `HEAD` + ETag check and `download(If-Match)`, else skipped; `render_glb_sandboxed` → unreadable / too large / crashed (skipped); a refusal is written as `save_version(failed, expected=READY)` + `drop_cover` in one unit of work. `RecheckReport` counts; `main()` logs one line and exits 1 if storage went down. A command, not a job kind: no schema change, run by hand once per rule change (and safe to repeat).
- **Data**: no migration. Plan of a page on the dev database (1,303 versions; the planner picks a seq scan at this size, the primary-key plan when the table is large):
  `Limit → Nested Loop → Index Scan using pk_asset_versions (Index Cond: id > …; Filter: status = 'ready') → Index Scan using pk_assets (Filter: kind = 'model')`.
- **Fixtures**: `glb_builder.dag_in_a_second_scene`, `dag_in_the_default_scene`, `cycle_in_a_second_scene` reproduce the reviewer's `dag.mjs` modes on the builder's cube.
