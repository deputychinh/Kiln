# KILN-10: Region annotations on images and comment threads

- Release: v0.2 · Status: done (score 9.5/10 after one improve round) · Owner: Claude (deliver-loop)

## Story

As a **lead reviewing an artist's image**, I want to mark a rectangle (or a pin) on a version's preview and write what is wrong there, and to leave plain comments on the version, so that the artist sees exactly where the change is needed and we can talk it through in one thread until it is resolved.

As an **artist**, I want to reply to each thread, fix my own wording or remove my comment, and see which threads are still open, so that I know what is left before the next version.

INVEST: Independent ☑ (needs only KILN-12's users and KILN-35's inspector) · Negotiable ☑ (pins before freehand, refetch before realtime) · Valuable ☑ (v0.2 "Review" is not reviewable without it) · Estimable ☑ · Small ☐ → built in four commits that each pass the gates (api + db, ui components, web feature, e2e) · Testable ☑

## Non-functional

- Security: OWASP ASVS 5.0 V8 (authorization in one policy, author-only edits), V1/V2 input rules (Unicode categories as for every other text field, bounded length and coordinates), API1/API5 (BOLA/BFLA by scope), CSRF and session/token rules from ADR 0013. Comment bodies are rendered as text, never HTML (React escapes; `white-space: pre-wrap`). No comment text in logs.
- Performance: a thread page is one query (keyset on the thread number through the unique index `uq_comment_threads_version_id_number`, root comment by the partial unique index, reply counts by `ix_comments_thread_id_created_at_id`, authors by `pk_users`); a reply page one query; bodies ≤ 2,000 characters, pages ≤ 100.
- Concurrency: thread numbers per version are taken under a per-version advisory lock (two parallel threads never share a number; the unique constraint is the backstop).
- Accessibility: WCAG 2.2 AA; regions are buttons with names ("Region 2: <start of the comment>"), focus visible on the image; a non-dragging way to mark a region (2.5.7); targets ≥ 24 px; status messages announced.

## Out of scope (follow-ups)

3D model annotations; freehand drawing, arrows and colours; @mentions and notifications; realtime updates (refetch on focus instead); deep links to a thread; comments carried over to a newer version; per-version comment counts on the gallery cards; attachments; reactions.

## Design

- **API** (OpenAPI regenerated, tag `comments`; every operation has both security schemes, 401/403/404/413/422/503 problem details): `GET|POST /api/v1/asset-versions/{version_id}/comment-threads` (threads by number, `limit` 1–100, default 50; create `201` + `Location: /api/v1/comment-threads/{id}`, optional `Idempotency-Key`), `GET|PATCH /api/v1/comment-threads/{thread_id}` (`{"resolved": bool}`), `GET|POST /api/v1/comment-threads/{thread_id}/comments` (replies oldest first; reply `201` + `Location: /api/v1/comments/{id}`), `GET|PATCH|DELETE /api/v1/comments/{comment_id}`. Bodies: `ThreadOut {id, version_id, number, region, comment, reply_count, resolved_at, resolved_by, created_at}`, `CommentOut {id, thread_id, author {id, display_name}, body, created_at, edited_at, deleted}`, `RegionOut {shape: rect|point, x, y, width, height}`. Codes: `COMMENT_THREAD_NOT_FOUND`, `COMMENT_NOT_FOUND`, `INVALID_COMMENT_BODY`, `INVALID_REGION`, `REGION_NOT_SUPPORTED`, `NOT_COMMENT_AUTHOR`, `COMMENT_DELETED`. CORS now allows `PATCH`.
- **Layers**: `routes/comments.py` → `services/comments.py` (`CommentService`: each use case one unit of work; loads the version and its asset and asks `authorize`) → `domain/comments.py` (`clean_comment_body`, `check_region`, `new_thread`, `new_reply`, `edit_comment`, `delete_comment`, `set_resolved`) and `domain/authorization.py` (`READ_COMMENTS` → read, `WRITE_COMMENTS` and `CHANGE_OWN_COMMENT` → write; author-only actions refuse a missing or other author) → `repositories/comments.py` (`SqlCommentStore` in the unit of work, `tx.comments`). Idempotency reuses `idempotency_keys` with a new `resource_id` column (`complete_resource`).
- **Data** (migration 0009, additive): `comment_threads` (number unique per version; region columns all NULL or a valid shape — checks `region_position`, `point_has_no_size`, `rect_inside_image` with explicit `IS NOT NULL`, because a CHECK passes on NULL; `resolved_by` iff `resolved_at`), `comments` (`is_root`, partial unique index `uq_comments_thread_id_root`; body 1–2,000 characters unless deleted, then empty), `idempotency_keys.resource_id` (nullable, metadata-only). New tables are empty, so their foreign keys validate at once and their indexes are built plainly; the foreign key to `asset_versions` takes a brief SHARE ROW EXCLUSIVE lock under env.py's 5 s `lock_timeout` (tested behind a writer). Cascades: deleting a version deletes its threads and comments. Threads are paged by number (not creation time: under the per-version advisory lock a thread created a moment earlier can take the later number); replies by `(created_at, id)`.
- **Web**: `features/comments/` — `useThreads(versionId)` (infinite query, `refetchOnWindowFocus: 'always'`), `useReplies(threadId)` (infinite, only when a thread is opened), mutations that refetch the version's threads; creates send an `Idempotency-Key` kept per draft, so a retry never posts twice. `CommentsPanel` (version picker, composer, "Show resolved (n)", thread list with four states), `ThreadItem` (first comment, Reply, Resolve/Reopen, Edit/Delete for own comments with an inline delete confirmation, replies collapsed to "Show n replies"), `RegionOverlay` over the preview (numbered rectangles and pins as buttons, a pointer drag or click while marking, a keyboard-movable draft). The inspector's tabs become Versions / Comments / Info (controlled), and while Comments is open the preview shows the chosen version; the chosen version and tab are local view state like the tab was (no deep link yet).
- **Marks** (review round 1): every region drawn or moved goes through `fitRegion` (at least 2 % a side, floored to six decimals, then shrunk by 1e-6 until x + width ≤ 1 in the same doubles the API adds). Badges are laid out in px from the measured image (`useElementSize`, `layoutBadges`): a rectangle's badge on its corner, a pin's centred on its point, each clamped inside the image, and one that would overlap an earlier badge moved to the nearest free place one 26 px stride away (up to six rings); a pin keeps an 8 px dot on its exact point. Without a measurement (tests, very old browsers) badges sit on their regions by percent.
- **UI package**: `TextArea` (label, hint, error, character count) with stories; `AssetThumb` takes an `overlay` drawn exactly over the image's box (not the letterbox), so normalised coordinates map to pixels.
- **Layout per size class**: compact — one column; the preview is full width, regions stay ≥ 24 px targets (pins 28 px), tabs below; medium — the same with the rail; expanded/large — the 320–400 px inspector: preview at the top, the panel scrolls with the pane. Long bodies wrap (`overflow-wrap: anywhere`, `white-space: pre-wrap`).

## Decisions for the reviewer

- Pixel size is not stored: a region is normalised to the image, and the 512 px previews keep the original's aspect ratio, so the same numbers fit the original. Storing width and height would need a worker change for no gain in v0.2.
- Comments belong to a version (a thread never moves to the next version), like ShotGrid notes; the panel's picker opens on the newest ready version.
- Threads are paged by number, not creation time (see Design); replies are a separate cursor list, so a long thread never bloats the thread page.
- A soft delete keeps the row with an empty body (the text is gone from the database), so replies keep their context; a deleted first comment leaves its region and thread.
- Anyone with write access can resolve, and replying does not reopen (Figma's behaviour). Editing and deleting are the author's alone, decided in `domain/authorization.py`, and refused by default when no author is given.
- The chosen tab, version and "Show resolved" are local view state, as the tab already was; there is no deep link to a thread yet.
- The new tables take their foreign keys and indexes directly (they are empty); the brief lock on `asset_versions` is bounded by `lock_timeout` and tested behind a writer.
- The annotation colour tokens went out in the `feat(web)` commit with the feature (they have no other user), and in that commit the web QA rows sat in the acceptance-criteria table by mistake; the e2e commit moves them.
- Tests were written next to the code rather than strictly first; the mutations above show the critical ones fail without the code.

## Known gaps (follow-ups)

3D model annotations; freehand drawing, arrows and colours; @mentions and notifications; realtime updates (refetch on focus only); deep links to a thread; carrying threads to a newer version; comment counts on gallery cards and on the Comments tab; the region overlay on the compare page; no cap on threads per version or replies per thread (pages bound reads, a cap would bound growth); a VoiceOver pass. Users with comments cannot be deleted (the author and resolver foreign keys are `NO ACTION`, like asset owners in ADR 0012): user deletion or deactivation must decide what happens to their comments.
