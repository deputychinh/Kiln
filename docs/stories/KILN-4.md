# KILN-4: Job queue on Postgres and a worker that makes image thumbnails

- Release: v0.1 · Status: done · Owner: Claude (deliver-loop)

## Story

As a **lead reviewing work in the gallery**, I want every uploaded image to get a small preview within seconds, so that I can scan a hundred textures without downloading each file.

INVEST: Independent ☑ (needs KILN-3 completion only) · Negotiable ☑ · Valuable ☑ · Estimable ☑ · Small ☑ (images only; `.glb` thumbnails are KILN-5) · Testable ☑

## Acceptance criteria

## Non-functional

- Security (A04/A06/A08/A10): only allow-listed decoders (`Image.open(..., formats=[...])`) so GD/PCF loaders with known bomb bypasses (CVE-2026-55380, CVE-2026-54059) are never reached; Pillow ≥ 12.3.0; header dimensions checked before `load()`; `DecompressionBombWarning` treated as an error; source bytes capped by the 500 MB upload limit; thumbnails never contain EXIF/GPS.
- Reliability: at-least-once delivery, idempotent processing keyed by `job_id` (re-running overwrites the same thumbnail key); lease + backoff; dead jobs visible.
- Performance: a 4096 × 4096 PNG thumbnails in under 2 s on a laptop; `Image.draft()` for JPEG; the worker streams the object, not more than one image in memory per worker.
- Observability: queue depth and failed count exposed by a `jobs` summary query (used later by the UI).

## Out of scope

- `.glb` thumbnails (KILN-5), purging orphaned staging objects and expired idempotency keys (KILN-22), a storage circuit breaker (KILN-23), AI tagging (KILN-13).

## Design

- Table `jobs(id uuid pk, kind text, version_id uuid fk, payload jsonb, status queued|running|done|dead, attempts int, run_after timestamptz, leased_until timestamptz, last_error text, created_at, updated_at)`; partial index on `(run_after) WHERE status = 'queued'`. `asset_versions.etag text` (migration `0003`).
- API: completion writes the ETag and the job in the unit of work (KILN-21 refactor).
- Worker (`services/worker`): `JobQueue` port with a Postgres adapter (claim with `SKIP LOCKED` and a lease), `ThumbnailProcessor` with `ObjectStorage` (shared adapter from `kiln_api`), a loop with backoff sleeps and graceful shutdown on SIGTERM.
- Failure reasons as an enum stored on the version (`failure_reason`).

### Design as built

- Migration `0003_jobs_and_processing`: `jobs` (one per version and kind, partial indexes on `run_after` for queued and `leased_until` for running jobs), `asset_versions.etag`, `asset_versions.failure_reason` with a check that it is set exactly when the status is `failed`, and `assets.cover_version_id`.
- API: completion heads the final object, then in one unit of work saves `processing` with the ETag and enqueues the job (outbox). `thumbnail_url` is a presigned GET of `thumbs/<asset_id>/<version_id>.webp` for ready image versions and for the asset's cover; `failure_reason` is returned on failed versions.
- `SqlJobQueue` (`kiln_api/repositories/jobs.py`): claim = `UPDATE … WHERE id = (SELECT … FOR UPDATE SKIP LOCKED LIMIT 1) RETURNING`, also reclaiming running jobs whose lease expired; `finish`, `retry`, `bury`, `counts`.
- Worker (`kiln_worker/runner.py`): built on the API's repositories and storage adapter; downloads into a `SpooledTemporaryFile` (16 MB in memory, then disk); a version that moved on meanwhile is skipped without overwriting; models are marked ready without a preview until KILN-5. `python -m kiln_worker` installs SIGTERM/SIGINT handlers and finishes the current job before stopping.
- Not built here (backlog): purging orphaned staging objects and expired keys (KILN-22), a storage circuit breaker (KILN-23), a health endpoint for the worker (logs carry job id, version id, outcome and duration).

### Review round 1 changes (8.0/10, reliability 0)

- **No job loops forever**: the loop catches every error (logged with the class and a traceback) and keeps running, also when the database is down; any unexpected error in a job is retried with backoff or buried; jobs that crashed the worker on every attempt are no longer leased again but buried with their version failed (`PROCESSING_GAVE_UP`).
- **Ownership**: `finish`, `retry` and `bury` only apply while the job is still `running` with the attempt number of this claim; a worker whose lease expired cannot overwrite the new owner's state, and finishing is the first statement of the outcome transaction.
- **Database clock** for leases and retries in production (`now()`), so skewed worker clocks agree; tests drive an explicit clock.
- **Give-up is safe** when the version changed at the last moment.
- **Memory**: shrink before applying EXIF orientation; peak for a 49 MP rotated PNG fell from 405 MB to 215 MB (PNG must decode every pixel, so about 220 MB per worker is the budget at the 50 MP limit; JPEG decodes at reduced size, about 14 MB).
- **TOCTOU**: the download is a `GetObject` with `If-Match` on the ETag from the `HEAD`; a change in between is `UPLOAD_CHANGED`. The integration test showed boto3's `download_fileobj` silently cannot do this (`IfMatch` is not an allowed extra arg), which the fake had hidden.
- **Migration 0003 backfill**: failed rows from before get `PROCESSING_GAVE_UP`; processing rows get a job; the worker accepts legacy rows without a recorded ETag.
- New tests (16) for each of these; the review's surviving mutants (no `SKIP LOCKED`, finish outside the transaction, busy loop) and a new one (no ownership guard) are killed.

### Review round 2 changes (fresh reviewer, 8.0/10)

- **Memory budget per job about 256 MB**, enforced by per-format pixel limits measured in fresh processes: PNG 50 MP (~4.4 B/pixel, full decode), JPEG 50 MP (decoded at reduced size), **WebP 12 MP** (~21 B/pixel with alpha, no reduced decode). A small 7000 × 7000 WebP that used to reach 823 MB is now refused before decoding. A regression test runs each format at its limit in a subprocess and asserts a peak below 300 MB. (This corrects the round-1 note that claimed about 220 MB for every format.)
- **AC8**: the worker logs `started (attempt n)` right after the claim and the outcome afterwards, so the job that crashes a worker is identifiable.
- **16-bit greyscale** (height and displacement maps) is scaled to 8-bit instead of clipped to white; palette transparency (`tRNS`) is kept as alpha; tests pin both and that JPEG is decoded at reduced size.
- **Times from the database** in production: the worker stamps versions with Postgres `now()` (`DatabaseClock`), like the queue's leases.
- `lock_exhausted` became `exhausted_jobs` (read only; burying is guarded by the claim).
- Filed **KILN-24**: lease heartbeat for jobs longer than the 5-minute lease (today safe because processing is idempotent).

### Review round 3 changes (8.5/10)

- **16-bit maps of 2048 px and more** failed as unreadable because `thumbnail()` uses `reduce()`, which rejects `I;16`; wide greyscale now resamples with `reducing_gap=None` (49 MP in about 108 MB). Flat 16-bit maps keep their level instead of turning black; maps whose minimum is not 0 use their full range.
- **WebP limit lowered to 8 MP**: lossless noise and animated RGBA WebPs at 12 MP reached 365–385 MB; at 8 MP the worst case measured is 234 MB. The memory regression test now covers lossy and lossless WebP, PNG, JPEG and 16-bit PNG at their limits.
- The database clock is pinned against a skewed local clock and the production wiring of `build_worker` is tested.
- Mutants killed: `reduce()` on 16-bit, span ignoring the minimum, flat map to black, local time in `DatabaseClock`, `SystemClock` wired into production.
