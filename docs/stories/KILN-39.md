# KILN-39 + KILN-51: A password policy against common and breached passwords; a review history nobody can truncate

- Release: v0.3 · Status: doing · Owner: Claude (deliver-loop) · Security debt from the KILN-12 and KILN-11 reviews (one story for both items)

## Story

As a **studio's Kiln admin**, I want `make create-user` to refuse a password that attackers try first — short, common, breached, or built on the service's name or the person's email — and to tell me why, so that no account starts with a password that a short online guessing run would find (KILN-39).

As a **lead or producer**, I want the review history to stay append-only even against a `TRUNCATE`, so that who approved what can never be wiped by a mistaken cleanup or a statement sent through the app's database login (KILN-51).

INVEST: Independent ☑ (KILN-12 and KILN-11 are done) · Negotiable ☑ (minimum length, list, context rule and the role split are choices, recorded in ADRs 0017 and 0018, superseded in part by 0019 and 0020 after review round 1) · Valuable ☑ (`password1234` was accepted; the history could be emptied in one statement) · Estimable ☑ · Small ☑ (one rule in the domain plus a list; one trigger) · Testable ☑

## Non-functional

- Security: OWASP ASVS 5.0 V6.2.1, V6.2.4 (since review round 1: ≥ 3,000 policy-matching entries), V6.2.9; NIST SP 800-63B-4 §3.1.1.2; Top 10:2025 A07 (authentication failures) and A08/A09 for the history's integrity. No password in logs, messages or test output.
- Performance: the lists cost one load per process that sets a password (about 0.02–0.05 s, about 20 MB RSS); the API never loads them; O(1) per check.
- Migrations: `lock_timeout` applies; `CREATE TRIGGER` takes a brief `SHARE ROW EXCLUSIVE` lock and rewrites nothing.

## Out of scope

- An online breach check (Have I Been Pwned k-anonymity): not added (ADR 0017 §6).
- Password change, reset, MFA: not built yet; a later change must call `check_new_password`.
- A non-owner runtime database role (KILN-51's second option): filed as KILN-58 with the accepted risk in ADR 0018.

## Design

- **Domain** (`domain/identity.py`): `check_new_password(password, *, email, blocklist, display_name)` checks `password_length` (visible code points after NFC, 15–128) and the NFKC form (≤ 512), then `password_key(password) in blocklist` (NFKC, case fold, NFKC, default-ignorables removed), then context: `password_context_words(email, display_name)` ("kiln", the local part, the domain labels but the last, the display name, and their pieces ≥ 3 characters, longest first) are removed until none is left; at least 15 of the password's own code points must remain and the rest must not be listed. Errors `WeakPasswordError` (`WEAK_PASSWORD`) and its subclasses `CommonPasswordError` (`COMMON_PASSWORD`) and `GuessablePasswordError` (`GUESSABLE_PASSWORD`), all 422, in `errors.py`.
- **Adapter**: `adapters.load_common_passwords()` reads `resources/common-passwords.txt` (unchanged upstream) and `resources/long-breached-passwords.txt` (the 15+ subset of Burnett's list) into one frozenset of `password_key` forms, cached per process; provenance, licences and checksums in `resources/common-passwords.LICENSE.txt`. `build_container` and the CLI pass the loader itself to `IdentityService`, which calls it only in `create_user` (ADR 0019).
- **Service**: `IdentityService.create_user` normalises the email, then checks the password against it, the display name and the list; it is the only place a password is chosen.
- **API contract**: `ErrorCode` gains `COMMON_PASSWORD` and `GUESSABLE_PASSWORD` (`openapi.json`, web types regenerated); no route changes.
- **Decisions**: ADR 0017 (15 characters, the list, context words, no breach API, existing passwords keep working), superseded in part by ADR 0019 (length in visible NFC code points, the key close to — not equal to — NFKC_Casefold, invisible characters stripped from the comparison, domain and display name as context words, the long breached list, loading only where a password is set).
- **KILN-51, data**: migration 0013 adds `review_events_no_truncate`, `BEFORE TRUNCATE … FOR EACH STATEMENT EXECUTE FUNCTION review_events_append_only()`; the function (0012) already raises for anything but the cascade delete, so its body is unchanged. `db/schema.py` creates the same trigger, so the definitions test covers it. The test fixture stops truncating and lets the history leave through the cascade from `asset_versions`.
- **KILN-51, roles**: the non-owner runtime role is deferred to KILN-58 (ADR 0018): it touches compose, env, settings, default privileges, CI, fixtures and e2e, and every existing database. The accepted risk is that the owner login can still disable the triggers.

## Decisions for the reviewer

- **15, not 12** (ADR 0017): a Kiln password is the only factor, which is NIST's 15-character case. At 15, only 329 of the NCSC list's 97,746 distinct entries can be reached, so review round 1 added 10,908 breached passwords of 15+ characters (ADR 0019) to meet ASVS V6.2.4's 3,000 policy-matching entries.
- **The NCSC 100k list** rather than SecLists' 10k: it is drawn from Have I Been Pwned's breach corpus (breached, not only common) and published by a national authority under the OGL. The file is byte-for-byte upstream, so its checksum can be compared with SecLists at `231fffb`. **Burnett's ten million** (public domain) supplies the long ones: the only licence-clear, breach-derived plaintext list with thousands of entries of 15+ characters. Only that subset is bundled (192 KB), with the upstream and derived checksums.
- **Context words as derivatives, not substrings**: NIST says the entire password is compared, not words inside it, so containing "kiln" is fine; a password is refused only when too little is left without the context words.
- **No HIBP opt-in**: the CLI runs a few times a year; an outbound call per account adds a third party and a failure mode for little gain over the offline list.
- **Existing passwords are not forced to change**; the README's quick start and the e2e user's password (33 characters) already pass.
