# KILN-6: Gallery and asset detail

- Release: v0.1 · Status: done · Owner: Claude (deliver-loop)

## Story

As a **lead reviewing a studio's work**, I want to scan every asset as a grid of previews and open one to see its versions and their processing state, so that I can find what changed and spot failed uploads without downloading files.

INVEST: Independent ☑ (reads the KILN-2/3/4 API only) · Negotiable ☑ · Valuable ☑ (first screen a person uses) · Estimable ☑ · Small ☑ (read-only; uploading from the browser is KILN-26) · Testable ☑

## Non-functional

- Security: the page renders API strings as text only (React escaping, no `dangerouslySetInnerHTML`); asset names are untrusted (A03); ids from the URL are passed through `encodeURIComponent`; thumbnails come from signed URLs the API issued (no URL built in the browser); no new secrets; CSP unaffected.
- Accessibility: WCAG 2.2 AA; status by text + colour; images have `alt` = asset name; one `role="status"` for loading; focus is not obscured by the sticky header (2.4.11, `scroll-padding-top`).
- Performance: polling keeps still-valid signed preview URLs of the same object (SigV4 `X-Amz-Date` + `X-Amz-Expires`, ≥ 2 min left) so the hero is not downloaded every 3 s; thumbnails `loading="lazy"`, `decoding="async"`, fixed `width`/`height` + `aspect-ratio` (CLS ≈ 0); route code-split; the list query is fresh for 5 min so signed URLs (and therefore image cache keys) do not change on every focus; pages of 24.
- Reliability: no retries on 4xx; 2 retries with backoff on network/5xx (TanStack default capped); polling is bounded.

## Out of scope

- Uploading from the browser (Dropzone, progress, completion) → **KILN-26** (added to v0.1; the phase-1 e2e "upload → thumbnail visible" lands there).
- Navigation bar / rail: Material 3 uses them for 3–5 destinations; v0.1 has one destination (Assets), so the bar arrives with the second destination (review queue, v0.2).
- Filters, search (KILN-15), versions compare (KILN-8), 3D viewer (KILN-9).
- Stable signed thumbnail URLs for browser caching → **KILN-27** (debt).

## Design

- API: unchanged (`GET /api/v1/assets?cursor&limit`, `GET /api/v1/assets/{id}`); types from `kiln.schema.ts`.
- Data: none.
- Web: `src/api/client.ts` (`apiGet` → typed JSON or an `ApiError` built from RFC 9457 problem details), `features/assets/{services,hooks,components}`; routes `/` (redirect), `/assets` (layout: gallery + outlet), `/assets/` (detail placeholder, expanded only), `/assets/$assetId`.
- UI package: `Badge`, `AssetThumb`, `Skeleton`, `EmptyState`, `ErrorState` (copy through props).
- UI (compact / medium / expanded): see AC10; the list pane is a CSS container so the grid column count follows the pane width (`auto-fill, minmax(min(160px, 40%), 1fr)`, so two columns at 390 px), not the viewport.

## Review rounds

- Round 1 (independent reviewer): 7.5/10 — flaky e2e (name collision), hero re-downloaded on every poll, gallery card stale after processing, focus/scroll lost going back and around Load more, silent failed polls, no h1 on the compact detail, ticking time, keyboard e2e used `focus()`, one 91-file commit. All fixed in round 2; round-2 fixes are split into ui / web / e2e / docs commits.

- Round 2 (fresh reviewer): 7.5/10 — the hero image never recovered after one failed load (the kept-URL logic kept the failed URL; reproduced with a 503 from storage), the gallery's image-error refresh could repeat every minute for a broken object, focus dropped to the body on compact loading/not-found states, the detail pane was a tab stop on compact screens, "100 polls" left in three docs. Round 3 fixes all of these; mutation checks 8 of 8 killed after adding a test for the one survivor (cached asset keeps heading focus). Accepted nit: a deep link on a wide screen shows the gallery's and the detail's loading statuses at the same time (two regions, each announced once).

- Round 3 (fresh reviewer): 8.5/10 — the gallery refreshed the whole list once per broken card (24 refreshes in a storage outage), the story's QA table cited a deleted test and stale counts, no h1 on compact error/not-found states, `new URL` could throw inside `structuralSharing`. Round 4 (beyond the 3-round limit, because each fix was small and cheaper than filing debt): one shared list refresh with `cancelRefetch: false`, `ErrorState` `titleAs` (h1 on compact), a parse guard, the QA table rebuilt from the real test names.

- Round 4 (fresh reviewer, final gate): **9.0/10, pass** (criterion 3 at 0.5 for M1, criterion 10 at 0.5 for the 91-file first commit and a three-fix commit). M1 — a preview failing while "Load more" was in flight used up the refresh window without refreshing — fixed after the gate (the refresh now waits until the page has loaded; test + 2 killed mutants, self-verified, not re-scored). L1 wording and constant name (`THUMB_REFRESH_WINDOW_MS`) fixed; L3 `ErrorState` title size noted in the CHANGELOG; L2 (no h1 while the compact detail loads) accepted.
