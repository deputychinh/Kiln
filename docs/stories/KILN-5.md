# KILN-5: Thumbnails for `.glb` models

- Release: v0.1 · Status: doing · Owner: Claude (deliver-loop)

## Story

As a **lead scanning the studio's assets**, I want every uploaded glTF model (`.glb`) to get a preview like images do, so that I can recognise props and characters in the gallery without opening each file in a 3D tool.

INVEST: Independent ☑ (KILN-4 queue and worker) · Negotiable ☑ (a still preview; the interactive viewer is KILN-9) · Valuable ☑ · Estimable ☑ · Small ☑ (one parser, one renderer, one migration) · Testable ☑

## Non-functional

- Security (A03/A04/A08): the GLB is untrusted input — every length, offset, count, stride, component type and index is checked against the buffers before use; no external URIs are ever fetched; JSON is parsed with the standard library and size-capped; no code paths run model-provided content.
- Performance (measured on an M-series laptop): real models render in well under a second (Khronos samples 0.03–0.6 s; 1,000,000 triangles in about 1 s). Hostile worst cases are bounded: drawing stops after 20 s and the model fails as `MODEL_TOO_LARGE` (2M overlapping full-frame triangles, fans or strips: refused after about 21 s, peak about 700 MB); a file of millions of empty chunks reads in 0.00 s at 96 MB; object lists longer than 100,000 entries are refused at once. Triangles smaller than a pixel are drawn as points.
- Containment: the reader and renderer run in a disposable child process (`spawn`). The worker kills it after 60 s (wall clock); the child also limits itself — 65 s of CPU (`RLIMIT_CPU`, on every platform) and it exits within a second if the worker that started it dies — so it never outlives its job, and a starting worker removes temporary model folders a killed worker left behind. On Linux the child also has a 2 GiB address space (`RLIMIT_AS`): allocations past it fail and end as `MODEL_TOO_LARGE`; every Khronos sample renders well inside it. macOS does not enforce address-space limits, so there only time is bounded. The model file is streamed into the sandbox, never held whole in the worker. A child killed by the kernel's OOM killer counts as too large; any other crash, or a child that ends without a preview, is retried as transient. Deployments should give the worker a stop grace period of at least 70 s so a render in progress can finish.
- Precision: positions are made relative to a point of the model in float64 before the float32 cast, so small parts of georeferenced or CAD scenes far from the origin keep their shape.
- Efficiency on hostile input: each accessor is decoded once (instances reuse it), the binary chunk is read through views (no copies), and only the vertices a primitive uses are transformed.
- Accessibility: previews are decorative in cards (`alt=""`) and named in the detail, as for images.

## Out of scope

- Textures and materials in previews (shaded neutral grey), Draco/meshopt decompression, `.gltf` with external files, animations and skins (rendered in bind pose), points and lines (not drawn), the interactive 3D viewer (KILN-9). Triangle strips and fans are drawn.

## References

- Khronos glTF 2.0 specification — GLB container, accessors, buffer views, node transforms: https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html
- glTF-Validator (the checks a reader must make on untrusted files): https://github.com/KhronosGroup/glTF-Validator
- Painter's algorithm and flat (Lambert) shading for previews: Foley et al., _Computer Graphics: Principles and Practice_, ch. 15–16.
- `references/security.md` (A03 injection, A04 insecure design: parse untrusted files defensively).

## Design

- `kiln_worker/glb.py`: `read_glb(data) -> Mesh` (float32 positions × 3 per triangle in world space) with explicit limits; errors `UnreadableModelError`, `ModelTooLargeError`.
- `kiln_worker/model_preview.py`: `render_model(mesh) -> bytes` (WebP) — fit, rotate 35° / −25°, orthographic, per-face Lambert shading with a key and fill light, painter's order, 2× supersampling.
- Runner: models download like images (ETag-checked) and render with the above; `FailureReason.UNREADABLE_MODEL`, `MODEL_TOO_LARGE`.
- Migration `0005_model_previews`: failure-reason check gains the two reasons; ready model versions go back to `processing`, their jobs re-queued.
- API: `thumbnail_url` for every kind.

## Review rounds

- Round 1 (independent reviewer): 6.5/10, security 0 — a 1.2 KB file with nodes sharing children made the walk double per level (months of CPU with the lease kept alive); vertex data was unbudgeted and re-read per instance (a 480 MB one-triangle file peaked at 3.7 GB); deep JSON, huge integers and wrongly typed fields crashed instead of failing as unreadable; model covers could point at previews that did not exist yet; float32 collapsed small parts far from the origin; texture-only required extensions were refused; the migration reset running jobs; strips and fans were silently skipped; the threat model and the mutation claim overstated the code. All fixed in round 2.

- Round 2 (fresh reviewer): 7.0/10, security 0 — a 64 MB file of 8.4M empty chunks made the reader allocate 2.47 GB (every chunk kept as a view); 3M empty nodes took 18.7 s; hostile renders took up to 49 s, not the documented ~15 s; 9 of 36 mutants survived; a test of non-finite input only checked the image size. Fixed in round 3: only the JSON and BIN chunks are read; object lists capped at 100,000; drawing budget of 20 s; one test per guard; docs give measured numbers.

- Round 3 (fresh reviewer): 7.0/10, security 0 — one mesh with 4,000,000 empty primitives referenced by 100,000 nodes (13 MB) would pin a worker for about 8 h (primitives re-resolved per node, skipped entries uncounted); an accessor decoded as indices could be reused as positions through a shared cache; an overflowing first instance poisoned the origin for the whole model; the migration could leave a model without a cover if an old worker was mid-job during the deploy (accepted: unlikely, and the next upload sets a cover).
- Round 4 (beyond the 3-round limit, because a security score of 0 cannot be left on `main`): three rounds each found a new input class, so the fix this time is structural — model previews run in a sandboxed child with time and memory limits (any future bomb ends as `MODEL_TOO_LARGE`) — plus the specific fixes: primitives resolved once per mesh and capped at 100,000, one decode cache per accessor role, the origin taken from the first finite instance. All reviewer hostile files rerun: refused in ≤ 0.25 s; 13 Khronos samples render in 0.04–0.64 s.

- Round 4 (fresh reviewer, with Linux runs in Docker): 8.5/10, security 1 — the sandbox contains every hostile file (57 tried), but its own guarantees were mostly untested (5 of 7 sandbox mutants survived); a render child outlived a SIGKILLed worker (17 s more, temp copy left); a failed memory limit on Linux was silent; the docs overstated the sandbox on macOS; a child ending without a preview raised an untyped error; the worker held the whole file in memory. Round 5: the child limits its own CPU time and exits when its worker dies; injectable child bodies make kill, crash, missing-preview and limit behaviour testable (10 of 10 sandbox mutants killed); a failed memory limit is logged on Linux; the file is streamed; stale folders are removed at start-up; the docs state the macOS gap.
