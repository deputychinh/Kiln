# KILN-12: Sign-in (Argon2id, session cookie) and personal access tokens

- Release: v0.2 · Status: doing (built and verified; independent review pending) · Owner: Claude (deliver-loop)

## Story

As a **studio artist or lead**, I want to sign in to Kiln with my email and password, and to give the CLI and Blender a token of their own, so that only people of my studio see and change our assets, and every asset and version says who made it.

As the **studio's Kiln admin**, I create each account with `make create-user`: **there is no public sign-up in v0.2.**

INVEST: Independent ☑ (identity context; assets only gain an owner) · Negotiable ☑ · Valuable ☑ (v0.2 cannot ship review without people) · Estimable ☑ · Small ☐ → built in five commits (db + domain, api, web, e2e, docs) · Testable ☑

## Non-functional

- Security: OWASP ASVS 5.0 L2 for V6 (authentication), V7 (sessions), V8 (authorization); Top 10:2025 A01, A04, A07. No secret, password, token, cookie or email in logs (sign-in failures log a 12-character prefix of the account-key hash).
- Performance: a session or token check is one indexed join (`pk_sessions` / `uq_access_tokens_token_hash` → `pk_users`); sign-in is one Argon2id (≈ 20 ms) plus three short statements; throttling is one bitmap-OR over two indexes.
- Accessibility: WCAG 2.2 AA; targets 44 px; errors as text tied with `aria-describedby`; focus to the first invalid field, to the page heading on navigation, back to the trigger on Escape.

## Out of scope

Public sign-up, password reset and change, e-mail verification, MFA/passkeys, user deactivation, roles (lead vs artist), per-user or per-project privacy (multi-tenancy: ADR 0012 keeps it to one place), SSO, the CLI and Blender sending tokens (KILN-16, KILN-17).

## Design

- **API** (OpenAPI regenerated; security schemes `sessionCookie` and `accessToken` on every protected operation; 401 with `WWW-Authenticate`, 403, 429 with `Retry-After` as problem details): `POST /api/v1/sessions` (201, cookie, `Location: /api/v1/sessions/current`), `DELETE /api/v1/sessions/current` (204), `GET /api/v1/me`, `GET|POST /api/v1/me/tokens`, `DELETE /api/v1/me/tokens/{id}` (204). Assets: `owner_id` on assets, `uploaded_by` on versions. Codes: `UNAUTHENTICATED`, `INVALID_CREDENTIALS`, `SIGN_IN_THROTTLED`, `CSRF_CHECK_FAILED`, `INSUFFICIENT_SCOPE`, `SESSION_REQUIRED`, `ACCESS_TOKEN_NOT_FOUND`, `ACCESS_TOKEN_LIMIT`, `INVALID_TOKEN_NAME` (+ the create-user codes).
- **Layers**: `authentication.py` (dependency: Bearer first, then the cookie, then the CSRF check) → `services/identity.py` (`IdentityService`) and `services/assets.py` (every use case takes the principal) → `domain/identity.py` (rules, secrets, expiry) and `domain/authorization.py` (the one policy) → `repositories/identity.py` (`SqlIdentityStore`) and `adapters.Argon2PasswordHasher`. Operator command: `kiln_api/cli.py` (`make create-user`).
- **Data**: migration 0006 (additive: `users`, `sessions`, `access_tokens`, `sign_in_failures`; nullable `assets.owner_id` and `asset_versions.uploaded_by` — metadata-only, no rewrite) and 0007 (idempotency keys per user: dropped, `user_id` added, primary key `(user_id, key)`). Checks: lower-case email, Argon2id PHC prefix, 32-byte hashes, scopes ⊆ {read, write}. Old failures are deleted with each new one and dead sessions at each sign-in, so neither table needs the worker. Plans on the dev database: session lookup `Index Scan using pk_sessions` → `pk_users`; token lookup `Index Scan using uq_access_tokens_token_hash` → `pk_users`; throttling `BitmapOr` of `ix_sign_in_failures_account_key_created_at` and `ix_sign_in_failures_client_ip_created_at`.
- **Web**: routes behind a pathless `_app` layout whose `beforeLoad` loads `/api/v1/me` (401 → `/sign-in?redirect=…`); `/sign-in` outside the shell; `/settings`. A 401 `UNAUTHENTICATED` from any other query or mutation sends the person to sign-in with `expired`. The browser calls `/api/v1` on its own origin (Vite proxy, ADR 0013). State: who is signed in — query `['me']`; tokens — query `['me','tokens']`; the new secret — local state of the Settings page only (gone on Done or leaving); form fields — local.
- **Layout per size class**: sign-in is one centred card (max 26 rem) under the brand, theme switch in the corner, at every width; the user menu is an avatar (44 px target) on compact and avatar + name + chevron from 840 px, a disclosure panel anchored to the end; Settings is one column capped at 60 rem, token rows stack on narrow containers and put facts and Revoke beside the name from 720 px (container query). Tokens used: surfaces raised/sunken/overlay/selected, `on-selected`, danger/success, radius lg/xl, shadow 2/3, `--kiln-measure`; new component `TextField` in `@kiln/ui` (stories for default, hint, invalid, password, read-only, disabled). New colour pairs are existing ones (danger on sunken and raised, on-selected on surface-selected), already ≥ 4.5:1 in both themes (`docs/delivery/KILN-35/contrast.md`).
