`make ci` = lint + typecheck + test + build, identical to `.github/workflows/ci.yml`.

Every Python test has a 120 s time limit (`pytest-timeout`, in `pyproject.toml`): tests that start threads or processes (heartbeat, supervisor) fail instead of hanging CI when a regression stops them from ending.

## Principles

- Test behaviour, one behaviour per test, Arrange–Act–Assert; test names are sentences (`test_upload_is_rejected_when_the_file_type_is_unknown`).
- Fakes for ports (database, storage, clock, Claude) in `tests/fakes.py`; no network in tests; warnings are errors.
- Small sample files in `samples/` (CC0 or self-made), never real studio assets.
- E2E runs against the production build, never the dev server.
- Focus after an action is tested where it lands: read `document.activeElement` in the e2e, record `aria-invalid` and the described error at `focusin` for a field that shows an error, and check a focus ring's width and colour, not only its style (KILN-48). A web change that moves focus ships in the same green commit as its e2e update.
- Attack a database guard (trigger, check, function) as a role with only DML rights, through the `dml_role` fixture in `test_review_store.py` (named `<test database>_dml` by `dml_role_name`, so parallel suites on their own databases never share it, and dropped at teardown with `DROP OWNED BY` then `DROP ROLE`; the session fixture fails the run if it is left behind, KILN-62), not only as `kiln`, which is a superuser locally: the `search_path` hole of migration 0015 was invisible to every test that ran as the owner. Re-attack a guard that way in the same round whenever a condition is dropped from it (KILN-51).
- Run axe from a known scroll position (the top of the page): it counts a target under the sticky top bar as obscured, so a check after a click that scrolled can fail or pass by chance (KILN-11).
- Playwright empties `apps/web/test-results` at the start of every run: copy screenshots to `docs/delivery/<item>/screens/` before rerunning any spec, and screenshot the element under review (an e2e that clicked into a thread captured the list, not the marks).

## What the tests do not prove

- Tag quality from Claude: measured separately with a small hand-labelled eval set (`services/worker/evals/`), precision/recall reported in each release's changelog.
- That the add-on works inside a real Blender: checked by hand on Blender 4.2 LTS before every release that changes it.
- Performance with thousands of assets: measured only once a large seed exists (v0.4).
